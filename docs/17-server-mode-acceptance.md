# 17 server 模式：测试与验收方案

状态：**方案，未实施**（2026-11-26）。对应实施文档 [docs/16](16-server-mode.md)；用户故事编号（S）、阶段编号（M0、P0–P4）与事实编号沿用该文。**当前实施范围是 M0 最小路径**（单实例、无接管、文件留在卷上）；起点为 P0 及之后的条目在 M0 之后按需启动。所有验证使用临时目录、独立端口、本地假模型和虚构目标，不读取或改写正在使用的实例与项目数据，规则见[验收说明](../scripts/acceptance/README.md)与[贡献指南](../CONTRIBUTING.md)。

## 0. 原则

- **只测外部行为**：断言接口返回、账本里读得到的状态、进程与连接的可观察结果；不断言内部调用顺序、缓存结构或 SQL 文本。
- **每个行为修复配一条复现测试**，注释写清失败原因与边界。
- **失败必须可见**：没有跑的检查不算通过。需要数据库的测试在没有库时显式跳过并打印原因，gate 另有规则（第 3 节）。
- **门槛先量后定**：性能数字是初始门槛，首轮测量后按基线修订；拿不到的数据写「未测」，不写 0。
- **两平台同一套**：Windows 与 Linux 跑同一组检查，任一平台不减少项目。

## 3. 测试基础设施

- **测试用的 PostgreSQL**：一次性实例，地址由 `ZRCIN_TEST_PG_DSN` 给出。每个测试建自己的 schema，用完即删，互不可见，可以并行。
- **gate**：新增「PostgreSQL 契约测试」一步。缺库时 gate 明确失败并给出两个平台的安装指引，不静默跳过；确需跳过用显式开关，跳过记入构建清单的 `checks`。构建清单另记契约测试是否跑过与 PostgreSQL 的大版本。
- **起库的方式**（待确认，见 docs/16 §15）：有 Docker 时由 `scripts/test-pg.sh` 与 `scripts/test-pg.ps1` 起一个用完即删的容器并导出地址；没有 Docker 就用本机安装的 PostgreSQL，两个平台都有官方安装包。
- **日常 `go test`**：没有设置 `ZRCIN_TEST_PG_DSN` 时，PostgreSQL 那一份跳过并打印原因，桌面功能的开发循环不变慢。
- **多实例夹具**：实例的启动入口可以带着连接串、配置、实例编号、时钟与退出函数在测试进程内调用，不绑定固定端口。
- **假模型与虚构目标**：沿用宿主集成测试的本地假模型网关与 `scripts/acceptance/target.py`。
- **故障注入**：T5 用 `docker kill`、`docker pause`、`docker unpause`；网络分区通过给每个实例单独接一个可暂停的 TCP 代理容器来做。
- **竞态**：并发敏感的包继续跑 race 检测，命令见贡献指南。

## 7. 故障注入与端到端（T5）

整组共用一个前置环境：一台隔离的 Linux 主机或虚拟机；一份 compose 栈，端口与数据目录独立；本地假模型网关；`scripts/acceptance/target.py` 作虚构目标；至少两个隧道节点（docs/14 §7）；两个在跑的项目，其中一个有在跑的 run；一个已暂停的项目。

| 编号 | 场景 | 动作 | 期望 | 证据 |
| --- | --- | --- | --- | --- |
| E1 | 属主被杀 | `docker kill` 属主容器 | 60 秒内备用实例持有租约；在跑项目的暂停原因是 `failover`，run 被取消，意图回待派；已暂停的项目不变；接管记录存在；节点回连无需重新接入；没有重复派发 | 接管前后的账本导出、实例日志、反代访问日志、各时间点 |
| E2 | 属主被挂起后恢复 | `docker pause` 属主，等备用实例接管，再 `docker unpause` | 旧属主恢复后没有任何写入被接受，进入隔离并退出，被编排器重启为备用；期间没有重复回合 | 旧属主日志里的隔离记录、库里的纪元、run 列表 |
| E3 | 只有属主连不上数据库 | 暂停属主的数据库代理容器 | 属主在丢失阈值内判定丢失并退出；备用实例在租约过期后接管；断连期间属主的读写接口返回 503 | 同 E2，另加属主接口的状态码记录 |
| E4 | 数据库重启 | `docker restart` 数据库 | 中断短于丢失阈值时不触发隔离，项目继续；进行中的写返回错误且不留半个状态；长于阈值时结果与 E1 相同 | 接口返回、账本一致性检查 |
| E5 | 属主运行时启动备用实例 | 起第二个实例 | 属主的项目不被暂停，run 不被取消，会话标记不变；备用实例的页面可读 | 属主侧的状态对比、备用实例页面截图 |
| E6 | 同时启动与反代切换 | 两个实例同时起，观察节点相关路径的去向，再杀掉属主 | 恰一个持有租约；节点相关路径只到达属主；易主后 10 秒内不再发往旧属主 | 反代访问日志与健康检查记录 |
| E7 | 通知丢失 | 重启数据库使通知连接断开，或注入断连 | 备用实例上的写入在一个轮询间隔内被属主感知并唤醒 | 属主的唤醒日志与时间戳 |
| E8 | 属主缺位期间操作员操作 | 停掉备用实例使属主缺位，操作员编辑目标、发消息、点继续 | 编辑与消息被接受；继续被拒并提示「等待接管」；恢复备用实例并接管后状态正确 | 接口返回、接管后的项目页 |
| E9 | 接管期间使用控制台 | 浏览器打开控制台，重复 E1 | 页面可读；状态条依次显示「等待接管」和新属主；项目页显示「实例切换」 | 按现有 `.cjs` 脚本的方式截图与断言 |
| E10 | server 形态闭环冒烟 | 导入单模板夹具，跑一次从意图到报告 | 「导入、命中、可复核、可交付」跑通，报告检查全部通过；同时记录库体积与 WAL 量 | 报告与检查文件、库体积记录 |
| E11 | 回滚演练 | 去掉连接串，用同一个二进制在临时目录以桌面形态启动 | 桌面形态正常工作，通过现有的桌面验收 | 桌面验收输出 |
| E12 | 自动继续 | 打开一个项目的开关，杀掉属主 | 节点回连后项目自动继续，被中断的意图被重派一次；关闭开关的项目仍然暂停 | run 列表、派发记录 |

E10 的先例是 docs/01 第 9 节记录的单模板闭环。

## 9. 性能与容量门槛

都是初始门槛，首轮测量后修订。合成规模夹具沿用 `internal/store/scale_test.go` 的规模：4,000 条事实、500 个意图、5,000 条消息、1,000 个 run。

| 指标 | 夹具 | 初始门槛 |
| --- | --- | --- |
| 看板接口延迟 | 合成规模夹具 | PostgreSQL 上的 p95 不超过桌面形态的 5 倍，且不超过 500 ms |
| 打开带 5 万行版本日志的项目 | `scale_history_test.go` 的夹具 | 不超过 1 秒，且与版本日志长度无关 |
| 接管完成时间 | E1 | 属主死亡到项目可被操作员继续，不超过 60 秒 |
| 计划内交接 | L8 与对应的端到端场景 | 不超过 15 秒加证据窗口 |
| 反代切换 | E6 | 租约易主后 10 秒内节点相关路径不再发往旧属主 |
| 实例常驻内存 | 持有 10 个合成规模项目 | 不超过桌面形态的 2 倍 |
| 库体积与 WAL 量 | E10 的一次闭环 | 只记录，不设门槛 |
