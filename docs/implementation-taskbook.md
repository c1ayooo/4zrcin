# 天吴 · 指挥官—执行者架构实施任务书

状态：2026-11-18 定稿（经三轮对抗性审查）
位置：仓库 docs/implementation-taskbook.md；架构见 docs/01-architecture.md；实现约定见 agent.md。
说明：本文是当前实施任务书，不是历史阶段记录；完成后应删除或替换。文中不含绝对路径与外部平台引用，可在任意开发机（Linux 优先、Windows 兼容）执行。

## 0. 定稿结论

### 0.1 审查过程

本任务书经三轮、共 11 份独立对抗性审查：

- 第一轮（4 份）：早期 9 任务草案。结论：多数任务未命中真实瓶颈，部分环境/工具类设计违反仓库约定或不可达。
- 第二轮（3 份）：收缩版。结论：交接根因误诊（历史数据早于当前基线，基线已修交接/写者归属/释放）；停测匹配抓不到真实违规；历史提示词无法重建；部分接口不成立。
- 第三轮（4 份）：另一版智能体主线草案（A/T 编号体系）。结论：方向正确但按现文不可实施——工作量约 180–290 人日、重型契约回潮（约 50 字段/10 端点/新对象类型，而存储层明确不支持迁移）、平台方法矩阵违反“不教模型渗透”、端到端验收依赖容器/真实模型/判定隔离而不可执行、Linux 覆盖为零、多数主线任务在现有代码里已存在或与现有 board/intent/pump/collab 重复。

### 0.2 对前期草案的取舍

保留：角色决策权限、三条持续闭环（作为行为验收口径，不落新对象）、协作/复核/记忆/调度的方向、执行可靠性原则（不自动执行/重放、unknown、幂等、复核绑断言版本）。

删除或推迟：持久化计划/子目标/候选/局部工作状态等新对象；控制面排序与评分化；平台方法矩阵；全量端到端验收；重型事件/动作/证明/授权契约。

### 0.3 本期定位

先做 1–2 周的“止血与可测”，不追大架构。真实数据显示：平台代码无法改变目标防护；能提高真实渗透产出的，是工具面真实可用（harness 内置工具 + 模型自装）、Linux 工具环境、授权等待缩短、交接/指令不再丢失、环境失败不被误判为“技术不存在”。这些才是本期 P0。

### 0.4 口径

- 成本不做限制，也不做降本任务；token 只记录（运行用量/决策记录），不设阈值、不进指挥官提示词、不作为验收目标。
- 账本契约优先级低：本期不新增存储对象类型、不改 schema 版本、不新增持久计划对象；最多复用现有对象加只读投影。
- 保持事实意图架构：事实=节点，意图=边（前提事实 → 产出事实），指挥官给意图+前提，执行者执行并回写事实；verified_only、note 永不复核、复核绑断言版本不变。
- 全程遵守 agent.md；不教模型渗透（平台内容不含工具用法、攻击步骤、漏洞类别、产品名/CVE/固定顺序）。
- 目标运行环境：Linux 优先、Windows 兼容；本期新增代码不得引入 Windows-only 假设。

## 1. 指挥官—执行者契约（规范，本期不变）

1. 根方向由指挥官创建与派发；执行者可用现有 spawn/children 组织子方向。控制面只做准入、账本、取消、对账。
2. 执行者只拿到自己的意图、前提、约束、验收、上下文与证据契约；不接收整份目标，不接收打法教程。
3. 事实只来自执行者显式声明或受限且可证明的派生；无原始证据的观察只是线索（note）。
4. 外部动作可追溯、可对账、不盲目重放；未知效果显式保留。
5. 复核独立于执行者，按断言版本重跑；note 不复核；verified_only 不变。
6. 平台不生成策略：不判断任务类型、不提供对照步骤、不写战术、不排序攻击路径。
7. 工具由 harness 原生提供，模型可自行下载安装；平台只负责工具真实来源、健康与可发现性，不提供工具用法教程。

### P0-1 基线复现与本地 gate（1–2 人日）

目标：任何结论前先证明“测的是哪份代码”。

改动：重建控制面与嵌入前端、harness（含 scan）；构建、静态检查、测试与前端构建；生成构建清单（源码身份、工作树补丁摘要、二进制摘要、协议版本、真实模型 id）；本地 gate 脚本同时支持 bash 与 pwsh；当前无持续集成，用本地 gate 替代并在文档记录；核对本机构建产物与源码差距、harness 相关的目录/二进制环境变量。

验收：从清单可追溯到本次测试的源码与二进制；本地 gate 在 Linux 与 Windows 均能跑；真实模型 id 被记录（历史数据只有网关聚合名，无法归因）。

### P0-2 工具面与环境真实性（2–3 人日）

目标：让执行者真的能用上 harness 内置工具与模型自装工具，而不是“工具页说有、执行时为空”。

证据：harness 已内置大量工具与工具目录，但旧项目执行者读取工具目录为空、随后落地自建工具与模板；/api/tools 报告的根与 harness 实际解析根不一致。

改动：修复 /api/tools 默认根为 harness 实际解析目录（保留现有两处并标注来源）；工具清单/健康从 harness 运行时读取（不要用“文件存在”冒充“可用”）；Linux 下的 PATH/工具发现路径；执行者回写“工具不可用/已自装”作为声明数据（tag 或 note，平台只记录）；不新增工具预装、不内置工具用法。

验收：控制台工具来源与 harness 实际执行一致；在 Linux 上真实 harness 回合中执行者能发现并使用内置工具；执行者自装工具在运行记录中可追溯；平台不出现工具教程/任务类型判定。

### P0-3 交接/写者归属验证（0.5–1 人日）

目标：确认基线已修的交接问题在真实 harness 下成立，并定位残留写者归属问题。

证据：旧项目 46 轮交接全部无有效回执（占全部输入 token 约 11%）；账本笔记写者全为 operator（模型用控制面令牌以 operator 身份写）；当前基线已加回执校验、写者归属、两次释放、指令优先。

改动：不做新对象；用真实 harness 跑一次交接收敛 round-trip；补负测试（交接回执必须要求 commander 写者/当前 run；operator 回执不能假通过）；核对“操作员轮内写入被计为轮次 action”的残留；文档保持两次上限一致。

验收：真实回合中笔记回执有效、连续交接轮为 0；operator 写笔记不会被误判为指挥官交接；残留问题被显式记录并修复或写入已知限制。

### P0-4 操作员指令消费与停测可观测（1–2 人日）

目标：操作员的“新增资产/停测/授权”不再停留在“已投递但无人消费”。

证据：历史项目操作员消息 34 条；新增资产消息已投递但账本零事实零方向；停测后仍有该资产事实。

改动：只读可观测（已投递 vs 被引用/被消费）；操作员范围条目用独立 append-only 旁路文件（授权/停测，operator-only API 写入，不改进程内项目设置、不做 schema 迁移）；brief/board 展示；停测由操作员选择受影响方向后取消在跑 run（现有取消语义 + Hold），不按兴趣实体/标题自动匹配；停测时间之后出现的该资产事实在 board/复核中标注“停测后产生”（按时间派生）；写明同账户可绕过 API 的已知限制。

验收：新增资产消息可在仪表上看到是否被消费；停测条目在 brief/board 可见；操作员取消后方向进入 Hold 且记录原因；迟到事实被标注；不宣称逐请求强制隔离。

### P0-5 真实项目纵向回归 + 提示词金样（1–2 人日）

目标：用可机测的 7 项真实项目指标替代不可执行的“历史提示词重建/靶场能力判定”。

指标（只记录、不设目标）：
1. 交接回执有效率（commander 写者/当前 run；历史为 0）。
2. 操作员指令消费延迟（消息创建 → 被意图/回合引用）。
3. 停测后事实数（标注）。
4. 未消费已验证事实数（历史 10 条，其中可行动约 2–5 条）。
5. 方向停顿率（无新方向的指挥官轮 / 交接轮）。
6. 环境误判（环境类 note 与已验证结论的比例）。
7. 复核排队/执行耗时。

另加提示词/日志金样：事实/意图段、预算（现有事实预算与任务书预算常量）、不出现平台编写的工具用法/攻击步骤/任务类型判定；日志锚点用于回放被版本化段落（不做完整历史提示词重建）。

验收：指标可在历史项目只读副本与后续真实项目上重复计算；金样在 Linux/Windows 一致；token 只记录。

### P0-6 Linux/Windows 双平台自检（1 人日）

目标：为迁移做设计准备，不引入 Windows-only。

改动：新增代码使用 path/filepath、os 抽象、bash+pwsh 双脚本；检查现有 Windows 专属路径（宿主子进程环境、可执行文件规范化、孤儿进程清理等）在 Linux 的等价行为；文档写明 Linux 优先、Windows 兼容与未支持边界；隔离类能力（进程/网络）在 Windows 返回 unsupported_boundary，不宣称强制隔离。

验收：Linux 与 Windows 均能构建并运行本地 gate；新增脚本两平台可执行；不新增 Windows-only 分支。

### 可选：运行时凭据脱敏（1 人日）

目标：事实渲染到 brief/board/日志时已知凭据不出现明文；不改账本/证据/复核。复用现有脱敏函数扩展事实渲染；补运行时测试；不宣称 ACL 隔离。

## 3. 后续：智能体主线（条件触发，不排期）

进入条件：P0 指标可测且稳定；Linux 迁移完成；操作员基础设施（回调/出网/授权）明确；P0-2/P0-3/P0-4 验收通过。

| 主线能力 | 处置 | 说明 |
| --- | --- | --- |
| 角色运行接缝与所有权 | 验证为主 | 三会话/单写/单持有/准入/恢复已存在；只补指挥官动作归属与只读投影 |
| 目标分解/计划/候选 | 推迟 | 与现有 board 前沿/意图/候选重复；不新增计划对象类型；计划留在笔记+board，不落新表 |
| 全局决策/重规划 | 仅 Skill/提示词 | 无新对象；不写固定优先级/排序；控制面不算贡献 |
| 任务契约/上下文装配 | 最小扩展 | 意图已有标题/描述/文档/验收/前提；最多补不超过 4 个字段，不改对象类型 |
| 执行者局部规划/纠错 | 最小扩展 | 与交接重叠；最多补不超过 3 个字段，优先复用工作笔记/交接 |
| 多执行者协作/结果合并 | 验证 + 小切片 | 子任务/等待/消息/调度已存在；只补“就绪未派发”只读告警与并行/委派验证 |
| 复核反馈 | 验证 + 小改 | 复核/就绪/唯一在途已有；不削弱 verified_only；不改 Skill 的笼统拦截 |
| 记忆/接班 | 并入 P0-3 | 回执/写者归属已在基线修复；只做真实端到端与失败回灌 |
| 前沿调度/事件 | 推迟 | 自动准入/排序有越权风险；先做只读前沿与事件消费告警 |
| 深度能力/多步组合 | 删除平台方法矩阵 | 改为工具适配器契约 + 模型自有 Skill/内容；平台不提供任务类型方法 |
| 接口/CLI/视图 | 缩编 | 只留 2–3 个只读端点（计划/前沿/结果承接），不与前端另存可写计划 |
| 端到端验收 | 缩编 | 重建控制面 + 一次真实 harness 回合 + 本机隔离合成靶场 + 记录真实模型/版本 + Linux/Windows 等价命令；判定带外，不宣称隔离 |

执行可靠性类支撑（事件/动作/证明/授权/环境等）只在主线实际需要时按“最小切片”交付；重型契约与强隔离在“账本契约低优先级、实际可用即可”的前提下推迟或删除；进程/网络强隔离在单机同账户不可达，降为授权记录+受控代理+unsupported_boundary+文档已知限制。

## 6. 明确不做

1. 重型账本契约（持久化计划/子目标/候选/局部工作状态，实体/证明/尝试/事件/资源/授权版本化）。
2. 新对象类型/改 schema 版本/声称可回滚而旧二进制会丢字段的迁移。
3. 控制面自动建/派方向、自动执行/重放、自动升级授权、评分化排序、固定优先级。
4. 平台方法矩阵/任务类型方法/工具用法/漏洞类别/产品名/CVE/固定顺序（教渗透）。
5. 成本限制/降本目标；token 进提示词或作为评分。
6. 不可执行的验收：依赖容器/真实模型/判定隔离却无前提的“端到端能力”；宣称单机同账户强隔离/零触碰。
7. 多节点/多租户/目标侧隧道/浏览器登录态跨方向复用（后续单独评估）。
8. 版式化的多阶段历史文档；架构行为和已知限制只更新 docs/01-architecture.md。
